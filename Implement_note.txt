Professional Implementation Design
DR Price Evaluation Tool for Thailand Market
Platform: Windows 11 Pro · Language: Python 3.11+ · GUI Framework: PyQt6
Data Source: Yahoo Finance (yfinance) · Configuration: JSON-based DR registry

1. System Overview
A standalone desktop application that allows users to select any Thai-listed Depositary Receipt (DR), automatically fetch the underlying stock price and relevant foreign exchange rate, then display a dynamic pricing table (±10 ticks around the current price) with full recalculation on any manual input change.

Core capabilities:

Auto‑discovery of all listed Thai DRs from a central configuration file.

One‑click fetch of live underlying price & FX rate.

Instant recalculation of the DR indicative price (iNAV) for 21 price levels when either underlying price or exchange rate is modified.

Proper rounding to Thai stock exchange tick sizes.

Clean, modern, responsive UI with dark/light theme support.

3.2 Data Fetcher (data_fetcher.py)
Encapsulates all external API calls with caching and graceful fallback.

Features:

Uses yfinance to fetch delayed stock prices (15‑min delay for US, real‑time for some markets with premium, but enough for indicative pricing).

Caches results for 60 seconds to avoid rate‑limiting. The manual "Fetch Data"
button bypasses the cache (force‑refresh) via YahooFinanceFetcher.invalidate().

Price fallback: Yahoo Finance → TradingView Scanner. The scanner queries every
DR market with the correct exchange prefix (US: NASDAQ/NYSE/AMEX, HK: HKEX,
JP: TSE, CN: SSE/SZSE, SG: SGX, FR/DE: EURONEXT/XETR, DK: CPH, TW: TWSE,
VN: HOSE/HNX) — see YahooFinanceFetcher._tv_candidates().

Returns a FetchResult dataclass: (price, fx_rate, timestamp, error, price_source, fx_source).

Handles connection errors, invalid tickers, and empty results with a user‑friendly error state.

3.3 Calculation Engine (engine.py)
Responsible for generating the 21‑row price table. The iNAV formula:

text
iNAV (THB) = (Underlying_Price × FX_Rate) / Ratio
Tick Size & Rounding:
The Thai stock exchange (SET) defines tick sizes based on price ranges. The engine includes a tick‑size mapping function:

DR Price Range (THB)	Tick Size (THB)
< 2	0.01
2 – < 5	0.02
5 – < 10	0.05
10 – < 25	0.10
25 – < 100	0.25
100 – < 200	0.50
200 – < 400	1.00
≥ 400	2.00
Grid Generation Logic (as implemented in engine.py):

The grid does NOT step the underlying price. It anchors on the DR price: the
center row (level 0) is the current iNAV rounded half-up to the SET tick, then
10 steps are built above/below. Each step advances by the SET tick applicable
to the *current* level's price, so every quoted price is a valid SET price even
when the range crosses a tick band (e.g. …1.99 → 2.00 → 2.02 → 2.04…). Each
level's underlying price is implied back from the DR price.

python
def generate_price_table(underlying_price: float, fx_rate: float,
                         ratio: float) -> list[dict]:
    current_inav = (underlying_price * fx_rate) / ratio
    center = round_to_set_tick(current_inav)        # half-up to SET tick
    above = []
    price = center
    for _ in range(10):
        price = round_to_set_tick(price + get_set_tick(price))
        if price <= center:
            break
        above.append(price)
    below = []
    price = center
    for _ in range(10):
        price = round_to_set_tick(price - get_set_tick(price))
        if price <= 0 or price >= center:
            break
        below.append(price)
    ordered = list(reversed(below)) + [center] + above
    levels = []
    for i, dr in zip(range(-10, 11), ordered):
        implied_underlying = (dr * ratio) / fx_rate
        levels.append({
            "level": i,
            "dr_price": dr,
            "underlying_price": round(implied_underlying, 6),
            "fx_rate": fx_rate,
            "raw_dr": (implied_underlying * fx_rate) / ratio,
        })
    return levels

Note: the per-DR "underlying_tick_size" in dr_config.json is metadata only;
the engine derives the tick from the DR price at each level via
get_set_tick()/round_to_set_tick() (Decimal half-up, never Python's built-in
round()). round_to_set_tick() also floors positive prices to the minimum tick
(0.01) instead of returning 0.

Key UI Components:

DRSearchComboBox – Editable combo box with autocomplete, populated from dr_config.json. Matching is case-insensitive (MatchContains + CaseInsensitive), so `aapl`, `AAPL` or `AapL` all complete to AAPL01. Selecting a DR triggers an automatic fetch.

DREditorDialog (ui/dr_editor.py) – Modal dialog opened via the sidebar
"Add / Edit" button. Registers a new DR or edits the selected one. Fields:
DR symbol (locked when editing), underlying ticker, currency pair, ratio,
and optional market, name, underlying tick size. Validates required fields
and duplicate symbols, then persists the entry to dr_config.json and
refreshes the combo.

ParamPanel – Three QLineEdit fields for underlying price, exchange rate, and ratio. Ratio is read‑only. Underlying price and FX rate accept manual edits; every keystroke (with a 200 ms debounce) triggers table recalculation.

PriceTableView – A QTableWidget with custom styling: alternating row colors, highlighted center row (green background/white text). Columns: Level, Underlying Price, FX, Raw DR, SET DR. Table is readonly.

FetchButton – Manual refresh. During loading the button is disabled and shows
"Fetching..." (text only — the planned spinner.gif is NOT bundled).

StatusBar – Shows status messages (e.g. "Calculated 21 levels"). Errors
appear as an inline red label in the sidebar.

Theme Toggle – Instant switch between dark (default) and light mode using a global QSS switcher. The chosen theme is persisted in QSettings.

3.5 Controller (app_controller.py)
The brain that wires everything together:

text
User selects DR → Controller asks Config for details →
    triggers DataFetcher.fetch() → on success updates ParamPanel fields →
    triggers CalculationEngine.generate_table() → updates PriceTableView.

User edits Underlying Price or FX → signal with debounce →
    Controller re-runs CalculationEngine with new values → updates table.
Signal/Slot Connectivity (PyQt6):

python
class AppController(QObject):
    def __init__(self, config, fetcher, engine, view):
        # View signals
        view.dr_selected.connect(self.on_dr_selected)
        view.fetch_clicked.connect(self.on_fetch_clicked)
        view.params_changed.connect(self.on_params_changed)
        
    @Slot(str)
    def on_dr_selected(self, dr_symbol: str):
        cfg = self.config.get_config(dr_symbol)
        self.view.set_ratio(cfg["ratio"])
        self.on_fetch_clicked()   # auto-fetch
        
    @Slot()
    def on_fetch_clicked(self):
        dr = self.view.current_dr()
        cfg = self.config.get_config(dr)
        result = self.fetcher.fetch(cfg)
        if result.error:
            self.view.show_error(result.error)
        else:
            self.view.set_underlying_price(result.price)
            self.view.set_fx_rate(result.fx_rate)
            self.view.set_last_update(result.timestamp)
            self.recalculate()
            
    def recalculate(self):
        ul = self.view.underlying_price()
        fx = self.view.fx_rate()
        ratio = self.view.ratio()
        table = self.engine.generate_price_table(ul, fx, ratio)
        self.view.update_table(table)
A QTimer‑based debouncer on the parameter input fields prevents excessive recalculations while the user is typing.

3.6 Error Handling & Resilience
Network errors: Shown as an inline red error label under the DR selector with the fetcher's message (e.g. “Failed to fetch underlying price/FX from all data sources.”). The Fetch button doubles as retry. (As implemented — no separate banner or retry button.)

Invalid ticker: The same inline error label shows a graceful message and the fetch result is discarded.

Zero or negative inputs: Validation in ParamPanel – if FX or price is non‑positive, the offending field's border turns red (QSS "invalid" property) and an error message is shown; the table is not updated. (As implemented – no “N/A” row.)

Logging: All API calls and errors logged to a rotating file (dr_evaluator.log) using Python’s logging module.

3.7 Packaging & Distribution
Use PyInstaller (build.spec) to bundle the application for Windows 11. The spec uses COLLECT, producing a one‑folder bundle in dist\DRPriceEvaluator\ (not a single‑file .exe).

Include dr_config.json and a README.txt in the distribution folder.

The executable can be placed anywhere; it will look for the config file in the same directory.

Optionally, sign the executable with a code‑signing certificate for enterprise deployment.

8. Conclusion
This design delivers a professional, highly responsive, and user‑friendly DR evaluation tool that effortlessly scales to cover all Thai depositary receipts. By separating configuration from code, leveraging reliable open‑source libraries, and applying modern UI principles, the application becomes a trusted daily companion for traders and investors monitoring DR price relationships.

9. Web Port, Mobile UX & Security Hardening (2026‑10 addendum)
A self‑contained Streamlit port lives in web/ (own copies of engine.py,
set_tick.py, data_fetcher.py and dr_config.json, no PyQt dependency) and
deploys free via GitHub + Streamlit Community Cloud (main file web/app.py;
the site rebuilds on every push to main). Hugging Face Spaces was evaluated
and rejected: the Streamlit SDK was deprecated (Apr 2025) and Docker/Gradio
Spaces require a paid plan, while free Static Spaces cannot run Python.

Mobile UX (360–430px): full‑width fetch button (sidebar hides behind the menu
on phones), 2‑column metrics with full‑width status line, swipeable 5‑column
grid with hint caption, 16px inputs (prevents iOS auto‑zoom), 44–48px touch
targets via a responsive CSS block.

Security review findings (fixed): CSV formula‑injection sanitizing
(= + - @ | % leading chars) in desktop and web exports; strict DR‑editor
input charsets (symbol/ticker/pair/market) plus 60‑char name cap; error labels
forced to plain text; CR/LF neutralization in logs via utils/logger.safe();
atomic dr_config.json writes (temp + os.replace). No eval/exec/pickle/
subprocess in project code; all HTTP uses TLS with timeouts; no secrets in repo.
